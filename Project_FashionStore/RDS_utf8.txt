1.01 UC-01_ Login 
Functional Description
ID and Name:
UC-01 Login 
Created By:
Lâm Trí Thông
Date Created:
20/01/26
Primary Actor:
Staff, Admin, Customer
Secondary Actors:
Google Service
Description:
This use case describes how an authorized user (Customer, Staff, or Admin) accesses the system by entering valid credentials through the Login page UI. The system authenticates the user, establishes a session, and redirects the user to the appropriate home page based on their role.
Trigger:
The user clicks the “Login” button on the Login page after entering credentials, or clicks “Login with Google” on the Login page to authenticate using an external provider.
Preconditions:
The user is not currently authenticated in the system.
The Login page is accessible to the user.
The Authentication System is operational.
Postconditions:
The user is successfully authenticated.
A valid session or authentication token is created.
The user is redirected to the role-appropriate landing page (Customer Home, Staff Dashboard, or Admin Dashboard).
Normal Flow:
The user navigates to the Login page and enters username/email and password.
The user clicks the “Login” button on the Login page.
The System receives the login request and validates the input format.
The System authenticates the credentials against the Authentication System.
The System creates a session/token for the authenticated user.
The System identifies the user role (Customer, Staff, or Admin).
The System redirects the user to the corresponding home page based on role.
Alternative Flows:
Login via external authentication provider:
   The user clicks “Login with Google” on the Login page.   The System redirects the user to the external authentication provider.   Upon successful authentication, the System retrieves user identity information.
Exceptions:
Invalid credentials
The system detects incorrect username/email or password
The system displays an authentication error message
The Use Case terminates
Authentication service unavailable
The Authentication System is unreachable or not responding
The System display a service unavailable message
The Use Case terminates
Priority:
High
Business Rules:
BR1, BR2, BR3, BR4, BR5
Other Information:
This use case assumes that users already have valid accounts, requires secure encrypted authentication with a response time under 3 seconds, and is fully traceable to the Login UI flow, sequence diagram, and related test cases.

b. Business Rules
BR1
Credential Validation
Username/email and password must be provided and follow defined format rules.
BR2
Role-Based Access Control
Users are granted access based on assigned roles (Customer, Staff, Admin).
BR3
Authentication Policy
Only valid and active accounts can be authenticated.
BR4
Session Management 
A session or token must be created after successful authentication.
BR5
Security Constraint
User credentials must not be stored or transmitted in plain text.

1.05 UC-05_ View Order History
Functional Description
ID and Name:
UC-05  View Order History
Created By:
Lâm Trí Thông
Date Created:
20/01/26
Primary Actor:
Customer
Secondary Actors:
None
Description:
This use case allows an authenticated Customer to view the list of orders previously placed in the system. The system displays orders associated with the Customer account, including their order information and current status. This functionality enables customers to track their purchase history and monitor the progress of their orders.
Trigger:
The Customer clicks the “Order History” option from the user menu on the authenticated Customer dashboard.
Preconditions:
The Customer has successfully logged into the system.
The Customer account is active and not suspended.
The system database is available.
The Customer has at least accessed the dashboard page.
Postconditions:
The system displays a list of orders belonging to the Customer.
Each order is shown with basic information such as:
Order ID
Order date
Total amount
Current order status
No system data is modified.
Normal Flow:
Customer clicks the “Order History” menu item on the dashboard UI.
System receives the request and verifies the Customer’s authentication session.
System retrieves all orders associated with the Customer’s account from the database.
The System filters orders to ensure that only orders belonging to the Customer are retrieved.
The System sorts the order list by order creation date in descending order (newest first).
System displays the order history list on the Order History screen.
Customer views the displayed order history.
Alternative Flows:
Customer has no order history:
System determines that no orders exist for the Customer account.
System displays an informational message: “You have not placed any orders yet.”
System displays an empty Order History screen.
Exceptions:
 User session expired:
System detects that the Customer’s authentication session is invalid or expired.
System redirects the Customer to the Login screen.
System displays an error message: “Your session has expired. Please log in again.”
Database retrieval failure:
System fails to retrieve order data due to a database or connection error.
System logs the error for technical investigation.
System displays an error message: “Unable to load order history at this time. Please try again later.”
Priority:
Medium
Business Rules:
BR1, BR2, BR3, BR4
Other Information:
This use case assumes that each order is assigned a unique Order ID immediately after being created by the Customer, even before confirmation by Admin. The system is required to display only the orders belonging to the authenticated Customer and retrieve the data within acceptable performance limits (response time ≤ 3 seconds under normal conditions). From a non-functional perspective, the system must ensure data confidentiality and prevent unauthorized access to other customers’ order information. This use case is fully traceable to the corresponding sequence diagram, UI flow from Customer Dashboard to Order History screen, and related test cases for validation and verification purposes.

b. Business Rules
BR1
Order ownership
A Customer can only view orders created by their own account.
BR2
Order Visibility
Orders are visible once an Order ID has been generated, regardless of confirmation status.
BR3
Access control
Only authenticated Customers are authorized to access Order History.
BR4

Data integrity
Order data displayed must reflect the latest status stored in the system database.
